# shadcn registry blocks

Learnings from porting `shadcn` registry blocks (`pnpm dlx shadcn@latest add @<registry>/<block>`) into an existing app. For the *sequencing* of install-verbatim-then-adapt see the porting entry in `workflow/`; for the install's file-placement quirks see `tooling/`.

- **A control the block ships with no behaviour is a slot, not a control — fill it with the app's existing component that already does that job.** The block's header shipped a plain `Bell` with no handler and a "New Conversation" row; the right move was neither leaving the dead icon nor deleting the slot but mounting what the app already had: the real `NotificationCenter` (polls, badges unread, marks read) took the bell's place, the sidebar's create button called the app's own `TaskDialog` via `onNewTask`, the search icon opened the existing ⌘K command palette, and the app's `ThemeSwitch` joined the header. Grep the app for the component that already owns the capability before writing anything new — an icon that looks right but does nothing is the block's default failure mode. The same rule applies to the block's menu rows: Profile / Notifications / Help center / Agent training / Subscription had no handlers and no routes behind them, so they were replaced with the destinations the app actually has (Settings / Change password / Log out), each wired. Confidence: 0.8
- **Active/nav state must resolve against live app state, not a static array.** The block derived `isActive` by reading the flag off a hardcoded demo array, so exactly one row could ever be marked and the breadcrumb never tracked navigation. Replace it with a builder over the real model (`buildNavGroups(active)`) plus a flat lookup the header can resolve against (`activeNavItem(page)`), and put the reason in a comment so the next pass doesn't reintroduce the static read. Confidence: 0.8
- **Thread a real callback through the shell rather than synthesizing a global event.** `onOpenPalette={() => window.dispatchEvent(new KeyboardEvent("keydown", { key: "k", metaKey: true }))}` works by accident and breaks the moment the shortcut is rebound or another handler listens. Add the prop to the shell's signature and pass it down — the shell already threads every other handler the same way, so the synthesized event is the only inconsistent link in the chain. Catch it in the same turn and pull it. Confidence: 0.8
- **Before accepting the block's content-wrapper padding, check who already owns the gutters.** The block wraps children in `p-4 md:p-6`; if every page in the app sets its own padding, that wrapper double-pads all of them, and full-bleed surfaces (board, chat, flow map) lose the edge it exists to preserve. Read one page's own spacing first, then decide whether the shell adds a gutter or only `flex min-h-0 flex-1 flex-col` around the children. Dropping it is a two-line change that removes padding from every page at once. Confidence: 0.75
- **A demo avatar pointing at a remote URL is worse than no avatar — use a monogram fallback when the product has no user identity.** The block's `NavUser` rendered a fabricated person with a GitHub avatar that 404s. This app has one shared workspace password and no per-user record, so the trigger became a `SW` `AvatarFallback` in the accent tint, with the menu carrying the real destinations. Check the backend before assuming an identity is available; an endpoint that doesn't exist means the honest substitute is a monogram, not an invented name. Confidence: 0.8
- **When the block's data layer is replaced, delete the fields that only existed for the demo.** Carrying a `path?: string` alongside `page: Page` on the same type leaves two sources of truth where one is now unreachable. Drop it and leave the reasoning as a comment on the surviving field, so the next reader doesn't add hrefs back. Confidence: 0.75
- **A rounded shell whose children aren't clipped shows square corners at the top — `overflow-hidden` on the rounded ancestor is the whole fix.** `SidebarInset` ships `rounded-xl`, but the sticky header inside it paints an opaque `bg-background/80` surface straight over the top two corners, so "the top bar isn't rounded like the bottom" is a *clipping* defect, not a radius defect. One `overflow-hidden` on the inset clips the header **and** the page content to the radius it already had; don't start by hunting for a per-corner radius override on the header, and don't restate the radius on the child to compensate. Confidence: 0.8
- **"Expand sidebar → minimize → expand → content overflows" is not a sidebar bug: the shadcn inset ships `w-full`, and as a flex item its base width is the whole wrapper — wider than the space the sidebar gap leaves it.** The toggle never changed that arithmetic; it only re-measured it, and the widest descendant (ten `w-[296px] shrink-0` board columns) is what actually pushes past the viewport. Fix every level of the flex chain rather than the one visible box: `min-w-0` on the inset, on the shell's content wrapper, and on each page root, plus `overflow-hidden` where a page owns its own internal scroll — and a page root that declares `w-full` wants `min-w-0` in its place, since `w-full` is the class that reintroduces the base width. Say in the report that the collapse state is the *reveal*, not the cause. Confidence: 0.8
- **The block's logo belongs to the block's own product — swap it for the app's real lockup at the same slot and the same mark size, and read the app's brand module first.** The export names don't describe their roles (`Logo` was the full lockup, `LogoMark` the bare mark), so rendering the wrong one stacks the mark on top of the wordmark and it reads as the block's name. Grep the brand module, then render mark + wordmark in the block's slot, keeping the block's `tooltip` so the identity still surfaces when the rail collapses. Confidence: 0.75
- **An unlabelled nav group holding one row is a grouping defect — move the row into the labelled group it belongs with and delete the group it leaves.** A single item sitting above a labelled group reads as a heading that isn't one. After the move, the manifest's flat lookup (what the breadcrumb and active row resolve against) and the group count have to agree, so re-read the manifest rather than trusting the edit landed consistently. Confidence: 0.75
- **"Extra space on the right" in a settings rail is a fixed-width column, not padding — size it to content with a floor.** A `w-50` nav forced every label into the same 200px track, so long labels truncated while the right edge stayed empty regardless of label length. `w-max min-w-44` makes the rail exactly as wide as the longest label needs and puts the border against the text; keep the `truncate`, which now only engages past the floor. The fixed-width rail was also the reason an absolutely-positioned active marker was wrong — it was offset against the old gutter (`-left-3` → `-left-2`), so a width change means re-checking every positioned descendant of the rail. Confidence: 0.8
- **"The logo looks flat when collapsed" is the button's own padding clipping the mark — and the padding override belongs on the *button*, not the span inside it.** `SidebarMenuButton` collapses to `size-8! p-2!`, so the content box is 16px while the mark is 24px, and the button's `overflow-hidden` clips it — "flat" and "not actual size" are the same symptom. Two earlier passes got this wrong by padding the wrong element: `px-0` on the header+button centred the mark but left it flush to the rail edge, and `px-1` on the inner span just added inset inside an already-clipped box. The fix is `group-data-[collapsible=icon]:p-1!` on the **button** (the `!` is required — the primitive's own `p-2!` wins otherwise), so the mark renders at full 24px inside the 32px button and lines up with the nav icons below. The wordmark must still leave entirely (`group-data-[collapsible=icon]:hidden`) rather than `flex-1` inside a clipped rail. Read the primitive's collapsed class list before theorising about centring. Confidence: 0.85
- **A badge that already has `w-fit` can still render 300px wide, because the *row* stretches it.** The count badge in the `flex flex-wrap` toolbar resolved its default `flex-basis: auto` against remaining space and grew to fill it, so a one-character count became a wide pill and "make the width auto so it has a nice aspect ratio" was the tell. The call site needs `w-auto flex-none self-center` (plus the `h-*` that matches the neighbouring control) — the primitive is fine, the flex context is the bug. Size a badge to its content: it is a count, not a panel. Confidence: 0.8
- **Deleting an action from shared chrome means finding where it already lives before calling it done.** "Delete new task in top bar" is a delete *and* an implied relocation: the control already existed on the board's own page header beside the board's other actions. Grep for the surviving mount point and say where it went — and pull the now-dead prop through the whole chain (`AppHeader` → `AppShell` → `App.tsx`) plus the import it orphaned, or the shell keeps carrying a callback nobody calls. Shipping only the delete reads as dropping the feature. Confidence: 0.8
- **When he dictates a class name, treat the exact utility swap as the literal spec.** `change items-baseline to items-center` names both classes; do the swap, and note which variant the change does *not* affect so the reader knows the blast radius. This is the same rule as quoting a class list as a locator. A dictated *number* in prose works the same way — "make it padding left and right 4px" is `px-1`, and the four pixels are the spec, not a suggestion to re-derive the spacing from the surrounding rail. Confidence: 0.8
- **Reordering controls in a bar moves the separator that justified the old order.** A bare `switch position A and B` names two elements, so it is a literal swap — but the vertical divider's *reason* ("destinations vs app-wide controls") belongs to one of those groupings, so once they swap, the same divider cuts between two of the same group. Re-read the comment that justifies the divider and move it with the reorder, then say what each side of it now holds. The ordering argument worth making out loud: a segmented control (the theme switch) groups with the other controls, and the avatar closes the bar as the single identity affordance. Confidence: 0.8
