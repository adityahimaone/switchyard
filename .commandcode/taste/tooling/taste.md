- `agent-browser` **is** available for visual verification. Install with `npm i -g --allow-scripts=agent-browser agent-browser` — a plain `npm i -g agent-browser` skips the postinstall, so no browser binary lands — then `agent-browser install` to download Chrome. Check `agent-browser --version` before assuming it is unavailable. Confidence: 0.9
- `agent-browser` subcommands worth knowing: `open <url>`, `reload`, `screenshot <path>`, `eval "<js>"`, `a11y` (runs axe-core against the live page), `press <Key>`, `find first "<sel>" hover`, `fill "<sel>" <value>`, `click "<sel>"`, `snapshot -i` (interactive-only accessibility snapshot that prints numbered element refs), `click @e10` (click a ref from the snapshot), `wait --url "<glob>"`, `skills get core`. Args are bare positionals — `screenshot --path` is wrong. Confidence: 0.85
- `agent-browser` text-based selectors fail silently against buttons whose label is composed of an icon plus nested text (`click "text=Add provider"` and `click "button:has-text('Add provider')"` both no-op'd), and against repeated labels — `find text "Compact"` clicked the wrong element where `find nth 4 "[role=radio]"` hit the right one. Fall back in this order: `snapshot -i` → read the `@eN` ref → `agent-browser click @eN`, or target the structural role/nth directly. Reaching for the snapshot or a role selector immediately is faster than re-phrasing a text selector. Confidence: 0.85
- Don't chain `agent-browser open <url> && agent-browser a11y` in one shell call — the audit runs before the SPA has mounted and reports phantom findings (a bogus "no h1"). `open`, wait for the render, then `a11y` as a separate call; confirm with an `eval` that the expected heading exists before trusting a missing-element finding. Confidence: 0.85

- `git commit -F <msgfile>` resolves its path **relative to the current working directory**, not the repo root. A `..\\.git\\...` path written from a subdirectory (e.g. `web/`) fails; when committing a message file under `.git/`, run the command from the repo root with `.git/SY_COMMIT_MSG.txt`. Forward slashes. Confidence: 0.8
- For a mechanical single-token find/replace across many files, a Python script in `.scratch/` run with `python` beats `edit_file` per site; for a single file, `powershell -Command "(Get-Content '<path>' -Raw) -replace 'old','new' | Set-Content '<path>' -NoNewline"` does the whole file in one call. `-NoNewline` matters — without it PowerShell appends a trailing newline. Confidence: 0.8
- A file the Vite dev server is holding open can refuse a scripted `io.open(path, "w")` write with a lock/sharing error mid-sweep. The identical replace pairs run as `powershell -Command "$p='…'; $s=[IO.File]::ReadAllText($p); … ; [IO.File]::WriteAllText($p,$s)"` went through on the same file, so when a sweep script fails on the *write* and not on the logic, re-run the same pairs through PowerShell rather than debugging the Python. Confidence: 0.7
- `edit_file` whose `old_text` ends in a newline but whose `new_text` does not splices the next line onto the replacement. Deleting a trailing blank line to re-indent a function joined `function … {` and its first statement onto one line. Put the trailing newline on both sides or on neither. Confidence: 0.65
