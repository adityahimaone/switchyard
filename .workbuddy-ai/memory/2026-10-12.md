## Session 9: the branch/pull feature was dead on the backend — fixed, then surfaced in Chat

User: *"improve in feature chat in project still has not select branch (add button
git pull in select) and kanban create task still not cant pull git branch"*.

### Root cause: `ListGitBranches` / `GitPull` never reached git

Session 8's `internal/kanban/workspace_git.go` resolved the workspace with
`ResolveWorkspaceFile(ws, "")`. That helper is for a path *inside* a workspace:

- `cleanWorkspaceRelative("")` returns `invalid workspace path` for an empty
  relative path — so **every** call failed before `exec.Command` ran.
- `ResolveWorkspaceFile` also demands a non-empty `ws.ID`, and the user's
  `~/.hermes/workspaces.json` entries carry **only `path`** (no id, no name).

Proved with a throwaway `go run` probe against the real registry:

```
id="" name="" path="/Users/.../next-portfolio-blog" status="local"
   branches=[] err=invalid workspace path      ← every workspace, every time
```

So `GET /api/workspaces/{id}/branches` always 502'd and `POST .../git-pull`
always returned `success:false`. That is the whole reason the create-task Pull
button looked inert and Chat had no branch list.

### Fixes

1. **`workspaceRepoRoot(ws)`** — new helper that resolves the checkout directly
   (path → `localWorkspacePath` → `filepath.Abs`), rejects a remote host with a
   node-agent message, and never consults `ResolveWorkspaceFile`.
2. **`ListGitBranches` now returns `GitBranches{branches, current}`** — `current`
   from `git rev-parse --abbrev-ref HEAD`, empty on detached HEAD. The picker
   needs it to mark the checked-out branch.
3. **`GitCheckout(ws, branch)`** — new. Verifies the ref first (so an unknown
   name fails as `unknown branch`, not git's `pathspec did not match`), refuses
   `switchyard/*` task-worktree branches, and is deliberately **not forced** so a
   dirty tree fails loudly instead of carrying uncommitted work across branches.
4. **`hydrateWorkspaceIdentity`** in `workspace.go` — path-only registry entries
   now get a deterministic id (`workspaceSlug(base(path))`, deduped `-2`, `-3`)
   and a display name. Without this they are unaddressable by
   `/api/workspaces/{id}/...`, render as blank rows, collide as React keys, and
   **share one entry in the ping history**. Never overwrites a declared id/name.
5. **`FindWorkspace(idOrPath)`** — matches id, then path, then name, so a client
   holding a pre-hydration list still resolves.
6. **New route `POST /api/workspaces/{id}/git-checkout`** (+ inventory entry).
   Refusals come back as **200 + `success:false` + git's own message**, which is
   what the picker renders — not a 5xx.

### Frontend

- New shared **`web/src/components/git/branch-picker.tsx`** — select + Pull.
  `mode="switch"` checks the branch out (Chat); `mode="base"` only records the
  choice (New task, where it is the worktree start-point). `selectDisabled`
  locks the list while leaving Pull live. `compact` is the icon-only Pull for the
  composer's chip row. `feedback` routes results to a toast or an inline line.
- **Chat**: picker sits on the composer's metadata line right after the workspace
  chip; `activeWorkspaceID` resolves path → id, so it is absent for the `local`
  sentinel. Disabled while a run is live (switching under a running turn would
  move the tree the agent is editing).
- **New task**: the branch + Pull control **moved out of the Worktree-only gate**
  and out of the collapsed "Scope & safety" section, so it is visible as soon as
  a workspace is picked. Under Workspace isolation the list is locked (the card
  runs on whatever is checked out) and the help text says so; Pull is always live.
- `api.ts`: `WorkspaceBranches` type, `workspaceGitCheckout`, `encodeURIComponent`
  on the id.

## Session 10: Integration health grouped by role

User: *"improve in overview in Integration health can you grouping based category

### Where the category lives

`Integration` gained a `category: IntegrationCategoryId` field and
`INTEGRATION_CATEGORIES` was added to `components/ui/integration-card.tsx`, next
to the catalog it describes — the catalog is the single source of truth for the
eleven tools, so the grouping belongs with it rather than in the page.

Six groups, ordered by what acts on a card first (not alphabetically):
**Execution & models** (commandcode, hermes, deepseek, codex, omp) → **Design**
(pen.dev) → **Context** (codegraph) → **Verification** (e2e) → **Source control**
(git) → **Transport & workers** (node agent, tailscale).

⚠️ `OverviewPage.test.ts` asserts the exact catalog id order — the pre-existing
test at the top of that file. Adding a field is safe; reordering `INTEGRATIONS`
is not.

### The rollup rule

A group's `n/m` counts a tool as healthy only when **every registered worker**
reports it, and scores 0 while the agent is down or no worker has registered.

Deliberately strict: a per-device tally would let a category read green while one
worker cannot run any of it — the exact failure the table exists to surface, and
the one a reader scanning group headings would miss. The heading lamp is
**three-state** (ok / partial / down) because "some tools missing" is neither;
`warning` is the app's token for that middle case.

### Extracted `features/overview/integrationHealth.ts`

The device/state/group/health model moved out of `OverviewPage.tsx` into a pure
module — no React, no motion, no brand SVGs. `integrationGroups` takes the
category list as a parameter rather than importing it, which is what keeps
`integration-card.tsx`'s brand assets out of its graph. OverviewPage imports it
and re-exports nothing.

### ⚠️ How to run the frontend logic WITHOUT node_modules

`vitest` is not in the partial install (only its sub-packages are), so the unit
tests cannot run. The workaround that does work, and is worth repeating:

```sh
cd web
node node_modules/.pnpm/typescript@5.9.2/node_modules/typescript/bin/tsc \
  src/features/overview/integrationHealth.ts \
  --outDir /tmp/ihcheck --module commonjs --target es2020 --skipLibCheck
```

The `import type` is erased, so it emits runnable JS even though the `@/` type
import reports TS2307. Then `require()` the emitted `.js` from a plain Node
script and assert. The harness parses `INTEGRATIONS`/`INTEGRATION_CATEGORIES`
straight out of the `.tsx` so it exercises shipped data. **17/17 assertions
passed.** Gotcha hit: locating the array with `indexOf("[")` finds the `[]` in
`Integration[]` — search for `"= ["` instead.

## Session 11: composer selects get their own row, and the chat rail gets one column system

User: *"redesign in command prompt in feature chat make sure all select is not
collision and make it compact you can put the select in below container message
prompt / in redesign in sidebar i have issue in project collapse chevron project
name is not align with collapse Project"*.

The "sidebar" here is the **Chat page's project rail**, not `AppSidebar` /
`NavGroup` — `navGroups` carries no `subItems`, so `NavGroup`'s collapsible
branch never renders. Worth remembering: "sidebar" in this project is ambiguous.

### Composer: a `meta` slot on `PromptInput`

`PromptInput` gained a `meta?: ReactNode` prop rendered on **its own row between
the textarea and the action row**. Previously the Chat page passed all five
selects as `leadingAction`, i.e. into `flex min-h-8 items-center gap-1` next to
the Plus and Send buttons. That is the collision: measured at 768px the selects
squeezed Send to **16x32** — the code comment in `prompt-input.tsx` had been
documenting the bug for a while.

- `Composer` now takes `meta` (the chips) and keeps `controls` (Analyze button,
  upload/analyze status) in the action row.
- The meta row is `mt-1.5 flex min-w-0 flex-wrap items-center gap-1`. **`flex-wrap`
  is the collision guarantee** — a non-wrapping row can only resolve overflow by
  shrinking or clipping, which is what broke Send.
- `PROMPT_CHIP` became compact: `!h-7 gap-1 px-2 text-xs [&_svg]:!size-3.5`.
  `max-w-*` deliberately stays **at the call site** (96/112/128/112/144/112px) —
  one shared cap either clips the model or wastes 48px on the executor.
- The compact pull button in `branch-picker.tsx` went `size-8` → **`size-7`**, or
  a 32px round button made the 28px chip row 32px tall.
- The "execution needs a remote workspace" warning moved into the meta row with
  `w-full`, so it drops to its own line instead of squeezing the chips it is
  about.

### Rail: one chevron column, one indent system

New `RAIL_CHEVRON = "grid size-6 shrink-0 place-items-center"`, used by **both**
disclosure levels. Root cause of the reported misalignment: the `RailSection`
header rendered a **bare 14px glyph** (centre at 15px) while the project row used
a **24px button** (centre at 12px). No single padding value reconciles those, so
the column kinked exactly where the tree changes depth. A shared 24px box fixes it
by construction, and 24px is also the WCAG 2.5.8 minimum the bare glyph missed.

Columns now: chevron at 4px (`pl-1`), label/dot at 32px, name at 48px.
- Project row: dropped `gap-0.5` so the chevron box and name button abut; the
  name's `px-1` then puts the dot on 32px.
- Project name span gained `leading-5`, making the button exactly 32px tall so it
  centres on the 24px chevron box.
- Nested chats moved `ml-3` → **`ml-8 pl-1.5`**, i.e. 49px against the project
  name's 48px. They used to sit at **28px — left of their own parent's name**,
  which was the other half of the "not aligned" report.

### Verification (vitest unavailable, so standalone)

`/tmp/verify-geometry.mjs` — resolves **real px from real Tailwind** (`compile()`
on `web/src/index.css`) and reads **real class strings from the real source** via
the TypeScript parser, then asserts the arithmetic. **15/15 passed**, and a
5-mutation round (restore the row gap, re-outdent chats, drop a chip cap, shrink
the chevron box, remove `flex-wrap`) produced **7 failing checks** — the harness is
not vacuous.

Two harness traps worth keeping:
1. `lastIndexOf(".pl-1")` also matches **`.pl-1\.5`**, and Tailwind sorts `pl-1`
   before `pl-1.5`, so `pl-1` silently measured 6px. Match the selector to a
   boundary: `esc + "(?=[\\s,{])"`.
2. A JSX attribute's `parent` is the **`JsxAttributes` container**, not the
   element — climb to it or every tag name reads as `"?"`.

Gates: `tsc -b` **6164 → 6168**, and the entire delta is `TS7026` (JSX-any noise
in this degraded env, `lucide-react` / `motion` / `react` types unresolved). The
TS parser proves the real change is exactly **+1 JSX element per file**; no new
error codes, TS1804 x11 unchanged. `token-lint` **14 err / 0 warn** unchanged.
`contrast-glass.py` PASS. Confirmed empirically that Tailwind **4.2.2 still emits
leading `!`** (`!h-7` → `height: ... !important`), so the existing `PROMPT_CHIP`
convention is sound.
