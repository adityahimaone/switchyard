# 2026-10-12

## Session 9: the branch/pull feature was dead on the backend — fixed, then surfaced in Chat

User: *"improve in feature chat in project still has not select branch (add button
git pull in select) and kanban create task still not cant pull git branch"*.

### Root cause: `ListGitBranches` / `GitPull` never reached git

Session 8's `internal/kanban/workspace_git.go` resolved the workspace with
`ResolveWorkspaceFile(ws, "")`. That helper is for a path *inside* a workspace:

- `cleanWorkspaceRelative("")` returns `invalid workspace path` for an empty
  relative path — so **every** call failed before `exec.Command` ran.
- `ResolveWorkspaceFile` also demands a non-empty `ws.ID`, and the user's
  `~/.hermes/workspaces.json` entries carry **only `path`** (no id, no name).

Proved with a throwaway `go run` probe against the real registry:

```
id="" name="" path="/Users/.../next-portfolio-blog" status="local"
   branches=[] err=invalid workspace path      ← every workspace, every time
```

So `GET /api/workspaces/{id}/branches` always 502'd and `POST .../git-pull`
always returned `success:false`. That is the whole reason the create-task Pull
button looked inert and Chat had no branch list.

### Fixes

1. **`workspaceRepoRoot(ws)`** — new helper that resolves the checkout directly
   (path → `localWorkspacePath` → `filepath.Abs`), rejects a remote host with a
   node-agent message, and never consults `ResolveWorkspaceFile`.
2. **`ListGitBranches` now returns `GitBranches{branches, current}`** — `current`
   from `git rev-parse --abbrev-ref HEAD`, empty on detached HEAD. The picker
   needs it to mark the checked-out branch.
3. **`GitCheckout(ws, branch)`** — new. Verifies the ref first (so an unknown
   name fails as `unknown branch`, not git's `pathspec did not match`), refuses
   `switchyard/*` task-worktree branches, and is deliberately **not forced** so a
   dirty tree fails loudly instead of carrying uncommitted work across branches.
4. **`hydrateWorkspaceIdentity`** in `workspace.go` — path-only registry entries
   now get a deterministic id (`workspaceSlug(base(path))`, deduped `-2`, `-3`)
   and a display name. Without this they are unaddressable by
   `/api/workspaces/{id}/...`, render as blank rows, collide as React keys, and
   **share one entry in the ping history**. Never overwrites a declared id/name.
5. **`FindWorkspace(idOrPath)`** — matches id, then path, then name, so a client
   holding a pre-hydration list still resolves.
6. **New route `POST /api/workspaces/{id}/git-checkout`** (+ inventory entry).
   Refusals come back as **200 + `success:false` + git's own message**, which is
   what the picker renders — not a 5xx.

### Frontend

- New shared **`web/src/components/git/branch-picker.tsx`** — select + Pull.
  `mode="switch"` checks the branch out (Chat); `mode="base"` only records the
  choice (New task, where it is the worktree start-point). `selectDisabled`
  locks the list while leaving Pull live. `compact` is the icon-only Pull for the
  composer's chip row. `feedback` routes results to a toast or an inline line.
- **Chat**: picker sits on the composer's metadata line right after the workspace
  chip; `activeWorkspaceID` resolves path → id, so it is absent for the `local`
  sentinel. Disabled while a run is live (switching under a running turn would
  move the tree the agent is editing).
- **New task**: the branch + Pull control **moved out of the Worktree-only gate**
  and out of the collapsed "Scope & safety" section, so it is visible as soon as
  a workspace is picked. Under Workspace isolation the list is locked (the card
  runs on whatever is checked out) and the help text says so; Pull is always live.
- `api.ts`: `WorkspaceBranches` type, `workspaceGitCheckout`, `encodeURIComponent`
  on the id.
